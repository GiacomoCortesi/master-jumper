# Master Jumper Sbanfer — MVP

A single-level, first-person dive jumper. You auto-run down an office corridor. **Hold** a key to wind up, **release** to jump, then dive Superman-style over a pile of office chairs and old computers. Land on the strip past the pile to win. Hit the pile, the ceiling, or overshoot into the stairwell and the level soft-restarts.

There's no charge bar, no timing cue and no tutorial overlay. You learn the jump by feel.

## How to open and play

1. **Prerequisites:** UE 5.4 and a C++ toolchain. On Windows that's Visual Studio 2022 with the *Game development with C++* workload. On macOS it's Xcode.
2. **Build:** double-click `MasterJumper.uproject`. When asked *"The following modules are missing or built with a different engine version… Rebuild?"*, answer **Yes**. You can also right-click it, choose *Generate Visual Studio project files*, and build `MasterJumperEditor` / `Development Editor`.
3. **Create the Content assets (once):** in the editor, use **File → Execute Python Script…** and pick `Tools/setup_project.py`. You can also run this in the Output Log's `Python` mode:
   ```
   py "C:/path/to/master-jumper/Tools/setup_project.py"
   ```
   It imports the wall texture, creates the materials, bakes the meshes, creates the input action and Blueprints, and builds `LVL_OfficeCorridor_01`. It prints an OK/FAIL summary in the Output Log. It's safe to re-run, because it skips anything that already exists.
4. **Play:** open `Content/MasterJumper/Maps/LVL_OfficeCorridor_01` (it's also the editor startup map) and press **Play** (PIE).

**You can play before step 3.** `MJGameMode` is the project's global default game mode, and it builds the whole corridor, obstacle, gate and art from code at runtime. PIE in *any* map (even an empty one) gives you the full game with identical geometry. Step 3 only turns that geometry into real, editor-visible Content assets.

### Controls

| Input | Action |
|---|---|
| **Space**, **Left Mouse**, or **Gamepad A** — hold | Wind up (no feedback) |
| same key — release | Commit the jump: takeoff → dive → landing |
| same key after **CLEARED!** | Run again |
| Esc | Stop PIE |

There is no look input and no strafing. The camera is fixed.

### How the jump works (for testers)

- Each attempt you get **one jump**. A 0.6 s standstill comes first, then auto-run at 6 m/s.
- Holding longer gives a stronger, flatter-and-higher dive. Too short and you fall into the pile. Too long and you hit the ceiling or overshoot into the stairwell.
- *Where* you release also matters: the takeoff point is wherever you were running when you let go.
- The yellow tape stripes on the floor are 2 m apart. They're environmental rhythm cues, not UI.

## Content map

```
Content/MasterJumper/
├── Maps/        LVL_OfficeCorridor_01
├── Blueprints/  BP_MJ_Player, BP_MJ_LevelController, BP_MJ_ObstacleStack   (subclasses of the C++ classes)
├── Meshes/      SM_OfficeChair, SM_OfficeComputer, SM_POV_Arms, SM_CorridorWallPanel

├── Textures/    T_CorridorWall
└── Input/       IA_JumpCharge
```

The `.uasset` files are generated by `Tools/setup_project.py`, so they aren't in git yet. After running the script once, commit them (with Git LFS, see `.gitattributes`).

**The four required custom assets:**

| Asset | Made by | Notes |
|---|---|---|
| Corridor wall texture + material | `Tools/gen_wall_texture.py` → `SourceArt/Textures/T_CorridorWall.png` → `M_CorridorWall` | Off-white wall, blue-grey wainscot, dado rail, baseboard, panel seams. Mapped once per 4 m panel. |
| POV arms `SM_POV_Arms` | `UMJArtLibrary::BuildArt(PovArms)` | Both arms straight ahead, palms down, hands converging: one dive pose, used for both obstacle and gap dives. |
| Office chair `SM_OfficeChair` | `BuildArt(OfficeChair)` | Five-star base with casters, gas lift, seat, reclined backrest, armrests. |
| Office computer `SM_OfficeComputer` | `BuildArt(OfficeComputer)` | Beige desktop case, CRT monitor, keyboard. |

All art is stylised blockout built from code-defined boxes and cylinders with solid materials. The same code produces both the baked assets and the runtime fallback, so they can't drift apart.

## Code map (`Source/MasterJumper`)

| Brief module | Class / file |
|---|---|
| PlayerPawn | `AMJPlayer` (`MJPlayer.*`): kinematic swept capsule, auto-run, fixed camera, Enhanced Input hold/release |
| JumpStateMachine | `UMJJumpStateMachine`: `Running, Charging, Takeoff, Airborne, Landing, Failed, Succeeded`, validated transitions, logged as `LogMasterJumper: [Jump] A -> B` |
| JumpCharge | `FMJJumpCharge` (`MJJumpCharge.*`): hold timer, hold → strength curve, every tuning value |
| DivePresentation | `UMJDivePresentation`: shows the arms on `Airborne` (they slide in over 0.12 s), hides them otherwise |
| ObstacleVolume | `AMJObstacleStack`: blocking box + fail trigger + instanced chair/computer pile |
| LevelGate | `AMJLevelGate`: success when the player is grounded with their centre inside it |
| LevelController | `AMJLevelController`: start delay, fail → fade → soft restart, success freeze, kill plane, player start |
| (support) | `AMJCorridor` (environment), `AMJGameMode`, `AMJPlayerController`, `AMJHUD` (win/lose text only), `UMJArtLibrary` + `FMJMeshBuilder` (art), `MJLayout.h` (all level dimensions) |

Tuning lives on the **Charge** struct of `BP_MJ_Player` (or `AMJPlayer`). See `HANDOFF.md`.

## Acceptance checklist

| Test | How it is met | Verified |
|---|---|---|
| PIE starts in corridor POV | Global game mode spawns the corridor and the pawn at X = 0, eye height 160 cm | needs in-engine check |
| Hold shows no charge UI | `AMJHUD` draws only WIPEOUT / CLEARED text, and the camera doesn't react to charging | by code |
| Release → takeoff → dive arms → landing | State machine + `UMJDivePresentation` | needs in-engine check |
| Wrong timing or hold fails | Simulated: see below | `Tools/jump_sim.py` |
| Hitting the pile fails and restarts | Swept capsule blocked by `AMJObstacleStack` → `ReportFail` → fade → `StartAttempt` | needs in-engine check |
| Clearing and landing in the gate wins | `AMJLevelGate` → `ReportSuccess` → freeze + CLEARED | needs in-engine check |
| Camera never looks around | No look binding, `bUseControllerRotation* = false`, `bUsePawnControlRotation = false` | by code |
| Four required assets under Content | Created by `Tools/setup_project.py` | needs the script run once |
| README documents version, steps, controls | This file | ✓ |

**Smoke test (simulated, `python3 Tools/jump_sim.py`).** Ten-jump sessions by a player aiming at the sweet spot, with Gaussian timing error on both press and release:

| Timing error σ | Successes per 10 (median, p10 to p90) |
|---|---|
| 30 ms (well practiced) | 8 (6–10) |
| 50 ms (practiced) | 7 (4–8) |
| 70 ms | 5 (3–7) |
| 120 ms (sloppy, but aiming at the right spot) | 3 (1–5) |

The successful holds range from 0.48 to 0.67 s. The sweet spot is to press about 6.5 m before the pile and release about 3 m before it. That meets the brief's bar of "at least 2–3 / 10 with practiced timing" without being trivial, and a first-timer who doesn't know the aim point does much worse.

## Known limits

- **Not compiled or played in-engine yet** (no UE available where it was authored). An independent API review was done, but expect possible minor compile fixes on first build.
- Art is code-built blockout: boxes and cylinders, flat colours, one texture.
- Lighting is nine movable point lights with Lumen and auto-exposure. There's no baked lighting and no light-panel emissive.
- No SFX (the Phase 3 polish item was skipped).
- Movement is kinematic and doesn't use `CharacterMovementComponent`, so the jump is deterministic and matches the simulator. That means no slopes or steps, which this level doesn't need.
- In the editor viewport (outside PIE), corridor walls, the pile and the arms only appear after `setup_project.py` has baked the meshes. Floors, ceiling and doors always appear.
- Uses a 0.6 s pre-run standstill and a 1.1 s fail freeze plus a fade. Both are editable on `BP_MJ_LevelController`.
